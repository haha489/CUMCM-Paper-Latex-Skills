# 论文完善建议：单独交给作者

## 目的与边界

整篇撰写或审校结束时，独立交付 `论文完善建议.md`；只写一问时聚焦该问，只改摘要时聚焦摘要，不扩展为无关的全文审查。它集中说明当前稿还缺少什么、哪里可以提高表达质量、怎样配图更有帮助，作者决定是否继续改进。

使用 [建议模板](../assets/review/论文完善建议.md)，根据当前稿实际填写并删除无关项。没有看到论文或结果时，只能保留模板或标明待审，不能凭惯例诊断“缺少流程图”。文档不通过 `\input`、附录、截图或打包混入正式论文。

`evidence.json` 管关键结果来源；`写作核查.md` 管内部核查和构建记录；`论文完善建议.md` 面向作者。缺失工作的完整诊断以建议文档为主，其余记录只作定位或引用，避免三份重复清单。

## 检查四个层面

1. **关键内容与依据**：原题要求是否完整回答、核心图表/结果有无来源、存在什么冲突。只有确实影响答案或结论时才列为关键待核查。一般美化与可选分析不列成必做。
2. **整体思路与数据侧写**：总体流程是否易懂；开篇是否缺少能解释数据分布、时序、变量关系或空间特征的图。流程图没有必要或数据侧写不适用时说明理由。
3. **逐问结果配图**：按原题问数逐项盘点现有结果图、对应的核心答案以及改图/补图建议。建议说明图形如何帮助理解，不只写“加一张结果图”。
4. **排版与表达**：图表清晰度、字号、配色、轴单位、子图组织、图题、页面留白、重点数字、摘要与章节衔接。模型的详细改进与推广设想也可列入，但不进入正文“模型评价”的额外小节。

## 一条有用的建议

至少交代：**位置 → 观察到的问题 → 具体改法 → 所需依据/数据 → 预期阅读收益 → 作者选择**。位置优先给章节标题或图表标签，已核实 PDF 页码时可补页码；重排后更新，不能猜页码。

针对图的建议，写清图型、横纵轴/空间变量、单位、曲线或分组、数据来源、是否保留原表。例如：已有调度表但结果主要以文字描述，可建议在结果节增加甘特图，用横轴表示时间、纵轴表示资源、颜色表示任务；前提是已经保存了资源编号及开始/结束时间。这只是写法示例，不代表当前项目存在该问题。

按“关键待核查 / 优先完善 / 可选美化”标优先级，并说明“现有成果可直接制作 / 需补充数据或计算”。不估计未经验证的收益百分比，不把模型效果改善与图形更易读混为一谈。

## 作者决定与更新

- 每条初始为“待决定”，可记“采纳 / 暂缓 / 不采纳 / 已完成”。未回复不代表采纳。
- 优先给出最值得处理的几项，其后逐问列完整配图盘点；无需一次提出大量重复或低价值建议。
- 可选美化在本轮完成建议文档后就可交付，不为等待决定暂停其余写作，不逐项追问。用户已授权的调整直接完成，记录实际效果和状态。
- 关键缺口在独立文档及交付说明中准确报告，相关论断不超出证据；不能因为移出了正文清单，就把未完成研究标为完成。
- 缺点精简与补图是表达偏好，不触发更换算法、重新训练或大规模实验。需要额外研究的事项先写成具体建议，按本次用户授权范围执行。
