# 证据与代码还原

## 开始前确认

从上下文和现有文件读取比赛与年份、所选题号、各问要求、写作范围、成果根目录、当前结果版本。有题目和完整成果即可开写，不要求特定文件夹布局。没有赛题时可整理方法与结果，但不能宣称已覆盖全部题目要求。

先用文件列表和关键词定位代码入口、配置、运行日志、结果表、图片及解释文档，不自动执行整个项目。Notebook 的执行序号和输出只是线索，需核查它们是否对应当前单元与数据。对运行版本不明或多个相近结果，核对输入、参数、种子、输出时间与文件哈希；时间最新不一定是最终版本。

## 从实现还原数学

1. **读执行链**：入口 → 数据筛选 → 转换 → 模型/目标 → 求解 → 后处理 → 输出。未调用的函数、候选模型、被注释步骤不能写成已完成。
2. **建代码—数学映射**：把字段转为有意义的符号，记录单位、数组轴、索引范围、函数对应的模型式、边界处理。向量化实现需要恢复求和范围；程序计数从 0 开始不应制造数学索引错位。
3. **检查隐藏决策**：过滤阈值、缺失值口径、标准化拟合范围、优化惩罚项、初末状态、随机种子、停止条件、数值容差及结果聚合方式。
4. **分清三层**：数学模型是什么；求解算法做什么；软件实现哪些步骤。例如 OR-Tools 是工具，不能替代 CVRP 模型定义，也不能仅凭库名断言采用了某种搜索策略。
5. **查输出语义**：打印的是目标值还是带惩罚的目标？均值是逐样本还是逐组？概率是否已阈值化？训练结果是否被误命名为测试结果？
6. **回到赛题**：答案的对象、时间范围、单位、精度、所需附表是否逐项满足。发现实现与题意不同，明确差异及其影响，不能把正文公式改成理想版本后继续使用旧结果。

## 每问的工作记录

在 `写作核查.md` 记录以下信息即可，不另造一套重复笔记：

| 项目 | 内容 |
|---|---|
| 题目要求与答案位置 | 原题页/小问；对应正文节、表或结果文件 |
| 机制 / 数据处理 | 实际步骤、必要性、代码位置 |
| 模型与求解 | 变量、目标或关系式、约束、算法、运行版本 |
| 验证 | 做过什么、没做什么、能得出什么 |
| 接口 | 输入来自哪里，输出由哪一问使用 |
| 问题追踪 | 对应 `论文完善建议.md` 的条目编号、来源核查与处理状态 |

面向作者的缺口分析、改进选择和图表建议集中写入独立的 `论文完善建议.md`，按 [建议文档规则](revision-advice.md) 组织。`写作核查.md` 保留技术追踪，不重复详细建议；论文中不设置“缺失项说明”。必要的适用条件和结论限定仍在相应模型或结果处表达。

## evidence.json：关键结论记录

由写作者维护，不要求用户填写。初始化器生成空记录；真实项目补充示例结构如下（下列值只是结构说明，不能当论文数据）：

```json
{
  "schema_version": 1,
  "source_root": "/实际成果根目录",
  "questions": [
    {"id": "q01", "requirement": "原题要求", "status": "ready", "answer_location": "sections/q01.tex", "missing": []}
  ],
  "claims": [
    {
      "id": "q01-cost",
      "question": "q01",
      "statement": "某运行条件下的总成本",
      "status": "verified",
      "display": "核定后填入的数值及单位",
      "sources": [
        {"path": "results/summary.csv", "locator": "行的业务主键与列名", "kind": "result", "sha256": "可选的实际 SHA-256"}
      ],
      "derivation": "直接取值，或完整的换算/汇总算式"
    }
  ]
}
```

- `questions.status`：`ready`（题目要求完整）、`partial`（部分完成）、`missing`（缺少核心工作）。可选对比没做并不自动使本问变成 `partial`。
- `claims.status`：`verified`（已核对）、`derived`（从已核对结果算出）、`conflict`、`missing`。后两类不得出现在正式论文。
- `kind`：`result`、`log`、`executed_notebook`、`figure`、`source_document`、`code`。仅有代码不能支撑已经产生某个数值；已执行 Notebook 要指明输出单元及版本。
- `locator` 要能定位到具体表格、行列、日志段、PDF 页码或单元输出；“见文件”不是足够的定位。
- `display` 是论文统一显示文本，百分号等由脚本转义。`--write-results` 生成 `data/results.tex`；摘要与正文用 `\Result{q01-cost}` 引用同一文本。复杂公式由正常 LaTeX 编写，不塞进该纯文本字段。
- 结果记录主要覆盖关键数值、阈值、比较、性能与答案，不强求把所有常数和符号登记。非数值推导可记录为有来源的文字结论。

**检查脚本只能验证记录结构、文件存在及部分 LaTeX 问题，不能自动证明来源支持结论。** 必须人工/模型回看来源、核算表达，并检查遗漏的核心数字。

## 冲突与追踪

同一指标冲突时记录双方来源、运行范围、统计口径和影响章节；能查清原因就统一口径并保留说明，无法确认时不擅自选更漂亮的数。原始文件只读；重绘、换算、补充计算另存，并记录输入与步骤。

旧论文摘要里的结果只属于旧论文。即使研究对象相同，也不能替代当前项目的执行证据。图片数字无法清楚辨认时先找原始表，不凭图形目测补精确小数。
